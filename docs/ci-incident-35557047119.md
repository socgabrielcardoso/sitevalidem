# Falha do static-checks em 1a64714

## Diagnóstico

O [run 35557047119](https://github.com/socgabrielcardoso/sitevalidem/actions/runs/35557047119)
falhou no job `verify`, na etapa `Run core self test`, com `MODULE_NOT_FOUND`.
O workflow executou `node ci/selftest.mjs`, mas o arquivo e a pasta `ci` não
existiam naquele checkout. O job durou oito segundos.

O [diff de 1a64714](https://github.com/socgabrielcardoso/sitevalidem/commit/1a64714af482628c40573348e295cea75b50e8df)
adicionou somente `assets/favicon.svg`. O workflow que referenciava o teste
ausente já havia sido introduzido em `e2bba9f`.

## Correção mínima já existente

O commit [3f88a86](https://github.com/socgabrielcardoso/sitevalidem/commit/3f88a86cec5ae516239c74aa878466debdddc39e)
adicionou `ci/selftest.mjs`. Esse foi o ajuste necessário para satisfazer o
comando existente. O [run 35557049694](https://github.com/socgabrielcardoso/sitevalidem/actions/runs/35557049694)
passou nesse commit, antes desta investigação.

Uma nova tentativa do run antigo continua usando `1a64714`, que não contém o
arquivo. A validação da correção deve usar um commit que inclua o teste.

## Proteção adicional do workflow

A etapa de sintaxe registrou `find: 'ci': No such file or directory`, mas saiu
com código zero. O shell implícito executou `bash -e`; o pipeline adotou o
resultado bem-sucedido de `xargs` e ocultou o erro de `find`.

Foi adicionada uma linha na etapa de sintaxe:

```yaml
shell: bash
```

O [shell explícito do GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell)
usa `bash --noprofile --norc -eo pipefail`, propagando a falha de descoberta
de arquivos. A alteração não dispensa a existência de `ci/selftest.mjs`.

Também foram adicionados 32 casos de regressão, executados com
`node --test tests/*.test.mjs`. Eles cobrem preço, quantidade, pagamento,
entradas HAR, recálculo e exportação de evidências. O teste original continua
como uma etapa própria. Essas adições ampliam a validação; a correção histórica
permanece a inclusão do arquivo ausente.

## Anotações revisadas

| Nível | Conteúdo | Relação com a falha |
| --- | --- | --- |
| Failure | Processo terminou com código 1 | Consequência do arquivo ausente, confirmada pelo log |
| Warning | Actions com runtime Node 20 executadas em Node 24 | Aviso; checkout e setup-node concluíram com sucesso |
| Notice | Futura migração de ubuntu-latest para Ubuntu 26 | Aviso; sem relação com o arquivo ausente |

O Node do comando de teste era `22.23.2`. O aviso de runtime das actions
não indica que o teste foi executado em Node 20 ou Node 24.

## Verificação

Na reprodução local com Node `24.19.0`, o snapshot antigo retornou código 1
com `MODULE_NOT_FOUND`. O pipeline antigo retornou zero mesmo sem `ci`.
O pipeline explícito retornou 1 para diretório ausente e 123 para JavaScript
inválido. Com arquivos válidos, retornou zero.

Os 32 testes de regressão e o teste original passaram localmente. O workflow
continua configurado para Node 22; seu resultado remoto deve ser consultado
no run associado ao commit publicado.

```sh
bash --noprofile --norc -e -o pipefail -c 'find assets tests ci \( -name "*.js" -o -name "*.mjs" \) -print0 | xargs -0 -n1 node --check'
node ci/selftest.mjs
node --test tests/*.test.mjs
```
